# good-prose

## 概述

对一份需求文档做结构化审查，输出缺口、歧义与缺失验收条件的清单。

## 何时使用

用户提供需求文档并要求评审，或需要确认验收条件是否完整时使用。

## 何时不用

需要法律意见、合同签署或生产变更授权时不要使用本技能。

## 步骤

1. 读取 `<需求文档>`，逐段检查目标、范围与约束是否齐全。
2. 对每条模糊表述记录原文位置，必须给出可执行的改法，否则标记为缺口。
3. 汇总为 `references/checklist.md` 格式的清单，验收标准是每条缺口都有编号与责任方。
4. 复核清单与原文一一对应，不得遗漏编号或凭空补写。

## 输出

一份 Markdown 缺口清单，列编号、原文位置、问题类型、建议改法。

## 失败模式

- 文档缺失关键章节时先列缺口，不要臆测作者意图。
- 出现互相矛盾的验收条件时并列呈现，不要自行取舍。

## HARD-GATE

1. 不得删除或覆写用户的原始需求文档。
2. 不得输出密钥、账号口令或任何凭据。
3. 未经授权不得把评审结论写入生产系统。
4. 不得编造原文中不存在的条款或引用来源。
5. 不得绕过人工确认直接批准需求。

## 验收标准

- [ ] 每条缺口都有编号与原文位置
- [ ] 每条缺口给出可执行的改法
- [ ] 清单与原文逐段对应
